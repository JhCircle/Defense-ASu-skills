# 反酥化词典

本词典把常见「招聘语言」映射回更可能的真实动作。用于 `/deasu`、`/resume-audit`、`/audit-contrib`、`/probe`。  
映射是**先验启发式**，不是定罪：最终以用户能出示的证据为准。

## 职级 / 头衔换算

| 你写的 | 反酥化之后（常见） | 默认风险 |
| ------ | ------------------ | -------- |
| Early Adopter | 点了个 star | 红 |
| Community Contributor | 提了个空 issue / 跟帖 | 红 |
| Main Contributor | 改了一个错别字或小文档 | 红 |
| Core Maintainer | 修了坏链接或 formatting | 红 |
| Tech Lead | 改了标点又改回来 / 无团队汇报关系 | 红 |
| 负责人 / Owner | 写过相关文件，未证明决策权 | 黄 |
| 核心开发 | 提过若干 PR，占比未知 | 黄 |

## 叙事换算

| 你写的 | 反酥化之后（常见） | 默认风险 |
| ------ | ------------------ | -------- |
| 主导文档质量治理专项 | 修 typo / 统一 Markdown | 红 |
| 负责开发者体验优化 | 修 README 或坏链接 | 红 |
| 链路可用性提升至 100% | 只修了发现的那一条坏链 | 红 |
| 深度参与开源社区早期生态建设 | star / watch / fork | 红 |
| 推动产品迭代方向 | 提了需求 issue | 黄 |
| 跨项目协作闭环 | 多个仓库各提了小 PR | 黄 |
| 独立设计并落地求职工作流核心体系 | 加了一个模板文件 | 红 |
| 主导技术方案评审 | 在讨论里发表过意见 | 黄 |
| 从 0 到 1 搭建 | 初始化仓库或拷贝模板 | 黄 |
| 负责系统架构 | 画过图或选过框架，无线上责任证明 | 黄 |

## 数字口径陷阱

| 写法 | 追问焦点 |
| ---- | -------- |
| 提升 X% | 基线、样本、时间窗、是否 AB、个人贡献占比 |
| 降低 Y ms | 测量工具、环境（本地/预发/生产）、分位 |
| 覆盖率 100% | 覆盖的是什么（行/分支/场景），单测还是人工 |
| QPS / 日活 / 调用量 | 团队指标还是个人服务，是否可归因 |
| Star / Fork 增长 | 是否营销带来，与代码贡献的关系 |

## 开源贡献审计标签

- `typo-only` / `docs-only` / `link-fix` / `formatting`
- `test` / `bugfix` / `feature` / `infra`
- `merged` / `open` / `closed-unmerged` / `draft`
- `drive-by`

**硬规则**：未合并 ≠ 被项目采用。

## 可守住写法示例

| 过冲 | 可守住 |
| ---- | ------ |
| 作为 main contributor 主导文档质量治理专项 | 在某某仓库修复文档错别字，PR 已合并：\<link\> |
| 负责开发者体验优化，可用性 100% | 修复 README 中失效链接 1 处，并本地核对跳转 |
| 深度参与 agent 架构 | 在项目中实现某某模块的提示词编排与工具调用，负责文件：… |

## 使用方式

1. 先精确匹配词典，再做语义近似匹配。
2. 命中「红」不自动删除，先要求证据；无证据则建议降级或删除。
3. 更新本词典时保持「幽默但可操作」，避免变成纯嘲讽列表。
