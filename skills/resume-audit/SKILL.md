# /resume-audit：简历审计

对整份简历做结构化打标，而不是只改一两句文案。默认站在「懂行的面试官」视角。

## 工作流程

1. 读取简历（Markdown / HTML / PDF 文本 / 截图 OCR 结果）与可选的目标 JD。
2. 按模块扫描：教育、实习/工作、项目、开源、技能、自我评价/HR 开场白。
3. 对每条 bullet 打标签：`证据不足` `口径模糊` `团队冒领` `计划当完成` `数字无定义` `头衔过冲` `工具堆砌` `同义反复` `可核验`。
4. 汇总水分等级：`低` / `中` / `高` / `极高`，并给出判定依据（命中红旗数、无证据强主张占比）。
5. 输出修改优先级：必须删、必须降级、建议补证据、可保留。
6. 用户需要逐条还原叙事时转入 `/deasu`；开源段落转入 `/audit-contrib`；要生成去包装文件时转入 `/honest-resume`；要模拟面试时转入 `/probe`。

## 红旗速查

优先参考 [references/deasu-dictionary.md](../../references/deasu-dictionary.md)。常见红旗包括：

- 「主导 / Owner / 负责人 / 架构师」但无决策与交付边界；
- 「0→1 / 从零搭建」但无时间线、仓库或上线证据；
- 「提升 X% / 降低 Y ms / 覆盖率 100%」无口径、样本或对比基线；
- 「深度参与 / 核心开发」与职责描述只剩调包、改配置、写文档；
- 技能栏堆满框架名，经历中从未出现对应动作；
- 开源贡献只有 contribution graph 截图，无 PR 链接。

## 默认输出

1. 总评（水分等级 + 一句话）；
2. 红旗清单（按严重度排序）；
3. 分模块审计摘要；
4. 修改优先级清单；
5. 可选：复制到 `assets/claim-audit-report.html` 风格的本地审计报告（用户指定路径时再写文件）。

## 边界

- 审计结论必须可追溯到原文句子；禁止空洞的「整体不够真实」。
- 对优秀但表述普通的内容明确标 `可核验/可保留`，避免为反酥化而反酥化。
- 不把用户真实联系方式写入公开模板。
