# /deasu：经历反酥化

把招聘语言翻译回「实际做了什么」。反酥化不是否定求职者，而是在面试第二个问题到来之前，先把证据缺口摊开。

## 与 /asu 的关系

| ASu `/asu` | Defense-Asu `/deasu` |
| ---------- | ----------------- |
| 动作 → 系统能力 → 业务价值 → 结果证据 | 结果主张 → 证据 → 个人边界 → 真实动作 |
| 稳妥版 / 进取版定位 | 可守住版 / 过冲版定位 |
| 生成 HR 开场白 | 指出开场白里不可追问的句子 |

收到 ASu 输出或「酥化后」简历时，默认进入反酥化，而不是继续加码包装。

## 工作流程

1. 确认目标岗位、材料来源（原始经历 / 酥化稿 / 已投简历）和用途（自查 / 模拟面试官 / 改稿）。
2. 抽取所有强主张：头衔、Owner/主导、0→1、架构、覆盖率、性能数字、用户量、Star、跨项目治理等。
3. 对每条主张填写五列表：`原文 → 字面含义 → 最可能的真实动作 → 需要的证据 → 风险等级`。
4. 输出可守住版表述：保留事实，去掉无法在追问中站稳的修饰。
5. 列出最多 8 个「面试第二个问题」级追问，并标注当前材料能否回答。
6. 用户要做完整简历打标时转入 `/resume-audit`；要对照 GitHub 时转入 `/audit-contrib`；要生成诚实版文件时转入 `/honest-resume`；只要追问脚本时转入 `/probe`。

## 风险等级

- `绿`：有链接、diff、上线记录或可复述细节，表述与证据匹配。
- `黄`：事实可能成立，但口径模糊（团队 vs 个人、计划 vs 已完成、口径未定义）。
- `红`：强动词/数字/头衔缺乏证据，或与常见「酥化换算」高度同构（见 [references/deasu-dictionary.md](../../references/deasu-dictionary.md)）。

## 表达边界

- 不编造「其实你没做过」；证据不足时写「待核实」，不直接定罪。
- 正式职位、公司、时间、学历除非用户承认有误，否则不擅自改写为更低。
- 区分「包装过猛」与「欺诈」：前者给可守住改写，后者明确标红并建议删除。
- 不在输出中保留用户隐私字段到可被公开粘贴的模板文件。

## 默认输出

除非用户只要其中一项，否则按以下顺序交付：

1. 一句话总评（水分倾向：低 / 中 / 高）；
2. 强主张审计表；
3. 可守住版岗位定位与 2—4 条经历改写；
4. 原 HR 开场白中的高风险句 + 替换句；
5. 证据补强清单与追问清单。
